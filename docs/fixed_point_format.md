# Fixed-Point Format

## Overview

The DWT and IDWT implementations use fixed-point arithmetic for hardware-oriented DSP processing.

The default data and coefficient configuration uses signed 16-bit values:

```text
DATAW = 16
COEFW = 16
```

Wavelet coefficients generated by the accompanying Python utility are represented using Q15 fixed-point format.

## Q15 Representation

A signed Q15 value uses a 16-bit two's complement representation.

The conversion from a floating-point value is:

```text
fixed_value = round(real_value × 32768)
```

The resulting integer is limited to:

```text
-32768 to 32767
```

The approximate numerical interpretation is:

```text
real_value ≈ fixed_value / 32768
```

## Example Conversion

For example:

```text
0.5000 × 32768 = 16384
```

Therefore:

```text
0.5000 → 0x4000
```

For a negative value:

```text
-0.5000 × 32768 = -16384
```

The signed two's complement representation is:

```text
-0.5000 → 0xC000
```

## Audio Sample Representation

The default RTL configuration also uses 16-bit signed values for audio samples.

The approximate integer range is:

```text
-32768 to 32767
```

Stereo samples are packed into 32-bit AXI4-Stream words:

```text
{Right[15:0], Left[15:0]}
```

Each channel is treated as an independent signed fixed-point sample by the corresponding QMF processing core.

## Filter Accumulator Width

The default accumulator width is:

```text
ACCW = 64
```

The wider accumulator provides additional intermediate precision during multiply-accumulate operations.

A filter multiplication using two signed 16-bit values can require up to 32 bits before accumulation.

Additional bits are required when multiple filter products are summed.

The final output is subsequently scaled using:

```text
OUT_SHIFT = 15
```

The default shift is intended to compensate for the Q15 coefficient scaling.

## Rounding and Saturation

The default configuration enables:

```text
ROUND    = 1
SATURATE = 1
```

Rounding reduces truncation bias when the wider internal accumulator is converted back to the output data width.

Saturation prevents an output value from wrapping when the computed result exceeds the representable range of the destination format.

The detailed implementation of rounding and saturation is defined by the underlying QMF and FIR processing cores.

## Quantization Effects

The Python wavelet definitions are originally represented using floating-point values.

Conversion to Q15 introduces coefficient quantization.

Therefore, the hardware implementation should not be expected to produce results that are numerically identical to a floating-point reference implementation.

Potential sources of numerical differences include:

* Q15 coefficient quantization.
* Intermediate fixed-point rounding.
* Output scaling.
* Saturation.
* Filter pipeline behavior.
* Decimation and interpolation timing.

Verification should therefore compare the hardware-oriented output against an appropriately quantized fixed-point reference where numerical accuracy is being evaluated.

## Future Precision Configurations

The top-level modules expose parameterized data and coefficient widths.

However, changing `DATAW`, `COEFW`, or `ACCW` requires verification of the complete processing chain.

This includes:

* AXI4-Lite coefficient writes.
* Coefficient memory file generation.
* QMF core parameterization.
* Output scaling.
* Testbench data interpretation.
* Software reference models.

The default 16-bit Q15 configuration should therefore be considered the primary validated configuration until additional parameter combinations are independently tested.
